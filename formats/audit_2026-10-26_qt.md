# Qt UI audit: deviations from Mastercam (2026-10-26)

Scope: `viewer-qt/src/*.cpp, *.h` in the main tree (<repo>, read as it stands; another
agent's uncommitted edits to mainwindow.cpp / viewwidget.cpp / testhooks.cpp were included). Read-only review; nothing fixed.

Rules checked against: the "no improvisation" HARD RULE (2026-10-14); the user's decisions in formats/user_decisions.md
(cited by id: Q19, Q33, SIM1-3, UI-1, ...); memory notes (Qt only, debranded name apprenticeCAM, startup risk modal ours).
The "Intentional deviations" lists in formats/provenance_audit.md were written by agents. Unless an item is also in
user_decisions.md, it is counted here as **not user-approved**.

Method: grep for markers (ours / inferred / measured / instead / fallback / TODO / NOT DECODED / mcamui), shortcuts and key
handling, QMessageBox / QFileDialog texts, hard-coded strings, colours and sizes. Then I read mainwindow.cpp, viewwidget.cpp,
dialogs8.cpp, simwin.cpp, managers.cpp, backstage.cpp, main.cpp and regenprogress.h in full, and sampled opdlg.cpp,
toolmgr.cpp, toolwiz.cpp, bpdlg.cpp, chaindlg.cpp, geopanel.cpp, expanel.cpp, stockdlg.cpp, acsettings.cpp and icons.cpp.

A recurring pattern: many comments cite **mcamui** (the deleted nuklear app) as the source of a look or behaviour. mcamui is
not a Mastercam source. The memory note "follow Mastercam over mcamui" applies, so an "as mcamui" comment without a
decomp / resource citation counts as unmarked improvisation here.

Impact: H = changes what the user's part / data / workflow does, or is visible everywhere. M = visible in normal use.
L = cosmetic or rare.
