## 1. Locating the archive
- Walk the part as `[u32 len][record]` (`tools/mcam_walk.py`). The record you want has u32 `+0x00` = 0x4000,
  i32 `+0x2c` = 36, u8 `+0x56` != 0. Source: `MastercamPlanes::WriteToDisk` builds the ent with `+0 = 0x4000`,
  `+4 = (u16) 1`, `+0x2c = 0x24`, `+0x56 = 1`, `+0x68 = this` and calls `write_ent_to_disk`.
- The archive is `record[0x68 : len]`. **Verified** on the 17 parts: a parse from `+0x68` ends exactly at the record end.
  (How write_ent_to_disk writes a ClassEnt is NOT DECODED; the offset comes from the data.)
- The root is not written with WriteObject: the stream starts straight with the `MastercamPlanes` level tag
  (`FF FF 04 00 0F 00 "MastercamPlanes"`) and SystemPlanes follows right after it (data).

## 2. MFC CArchive rules you need
(formats/part_tools.md "CArchive store rules"; MFC library code, not in the decomp; every case below occurs in the
user's parts and parses exactly.)
- One index table counts classes and objects together, starting at 1.
- **Level tag** (`ar.SerializeClass(X::GetThisClass())`, Ordinal_12658, at the start of every `X::Serialize`):
  `FF FF <u16 schema> <u16 len> <name>` adds class X (one index), or `0x8000 | i` refers to class i. The level's
  schema (`ar.GetObjectSchema()`, Ordinal_5880) = the schema written when that class first appeared.
- **WriteObject / ReadObject** (a pointer member, here only the map values): u16 `0x0000` = null; `0xFFFF ...` new
  class (one index) then the object (one more index); `0x8000 | i` = object of class i (one index); `i < 0x7FFF` =
  back reference to object i; `0x7FFF` + u32 = big tag (bit 31 set = class). Then the object's `Serialize` runs, which
  writes its **own level tag again** (as `0x8000 | i`).
- An embedded member (`member.Serialize(ar)` called directly) writes only its level tags.
- Count (`ReadCount`): u16; `0xFFFF` -> u32; `0xFFFFFFFF` -> u64.
- CString (FUN_1801704f0; AfxReadStringLength): u8 n; `0xFF` -> u16 n; u16 `0xFFFE` = UTF-16 marker, the length
  follows again (u8 / `FF`+u16 / `FF FFFF`+u32); u16 `0xFFFF` -> u32 n. Then n bytes (n x 2 if UTF-16).
- bool = 1 byte (FUN_180177d70), u32 = 4 (FUN_1800fd680), f64 = 8 (FUN_18042fa70). Little endian.

A C reader must keep the index table (an array of {kind, name, schema}) to resolve `0x8000 | i` tags; it can't be
skipped, because the tags are what separate the levels.

## 3. Grammar (load branches)
`tag(X)` = level tag, must name class X.

```
MastercamPlanes   tag(MastercamPlanes) -> schema S                         (Serialize 0x1802bc580)
  S == 4: SystemPlanes ; PlaneMap                                          (this+0x420 Serialize, FUN_1802a3560)
  S == 3: SystemPlanes ; i32 n ; n x { i32 kind ; kind 1: PlaneBase | kind 2: Plane }   (embedded, no WriteObject)
  S == 2: SystemPlanes ; u32 n ; n x Plane
  S == 1: SystemPlanes ; i64 n ; n x Plane
SystemPlanes      tag ; v<4: 6 bytes ; Matrix33 (+0x10) ; P3D (+0xe0) ; v<3: 4 bytes ;
                  4 x u32 (+0x110 active plane id per PlaneType, SystemPlanes::GetPlaneID) ;
                  4 x u32 (+0x120 active origin id per PlaneType, SystemPlanes::GetOriginID) ;
                  4 x Matrix33 (+0x130) ; 4 x P3D (+0x470) ; 4 x u32 (+0x530)        (0x180434090, v1..4)
PlaneMap          count n ; n x { CString key ; WriteObject(PlaneBase*) }   (CMapStringToOb::Serialize, Ordinal_12619)
  value class "Plane"     -> Plane
  value class "PlaneBase" -> PlaneBase
PlaneBase         tag ; v4 only: PlaneID (+0x10) ; Matrix33 (+0x40) ; CString name (+0x110) ; bool +0x118 ; bool +0x119
PlaneID           tag ; v1: GUID[16] (+0x10) ; i32 class (+0x28) ; i32 id (+0x2c)
Plane             tag ; v4: PlaneBase ; u32 +0x128 ; PlanePoint (+0x130) ; 3 x PlanePoint (+0x1b0, stride 0x80) ;
                  u32 +0x330 ; u32 +0x334 ; bool +0x338 ; u32 +0x33c ; u32 +0x340 ; u32 +0x344 ; u32 +0x348 ;
                  bool +0x34c ; u32 +0x350 ; bool +0x354 ; CString +0x358 ; bool +0x360 ; u32 +0x364 ; u32 +0x368 ;
                  bool +0x36c ; u32 +0x370 ; u32 +0x374
                  v1..3: i32 id (class 2, PlaneID(id, 2)), u32 +0x128, Matrix33, PlanePoint, 3 x PlanePoint, CString +0x110,
                  ... (see the decomp; not implemented, no sample)
PlanePoint        tag ; v1/2: P3D (+0x10) ; u32 ; u32 ; bool ; bool ; u8 ; bool ; f64 ; f64 ; bool ; f64 ; f64 ; bool ; u32
Matrix33          tag ; v1/2: 3 x P3D (+8, +0x38, +0x68)
P3D               tag ; v1/2: 4 x f64 (+8, +0x10, +0x18, +0x20)
```
Note the order in `Plane::Serialize`: the `Plane` level tag comes **before** `PlaneBase::Serialize` (the call is after
`SerializeClass`), so a Plane value reads `<Plane class/object tag> <Plane level tag> <PlaneBase tag> <PlaneID tag> GUID
class id <Matrix33 tag> 3x(<P3D tag> 32 bytes) name ...`.

### Where the id is
Per plane: the PlaneID inside PlaneBase: **i32 class, i32 id right after the 16-byte GUID**.
The map key repeats it: `FUN_1802a3660` writes `"%s~%d~%ld"` = `StringFromGUID2(GUID)` `~` class `~` id, e.g.
`{00000000-0000-0000-0000-000000000000}~2~7`. On load `FUN_1802a3370` rebuilds the std::map with
`FUN_1802a31d0(key)` as the map key (split on `~`: IIDFromString, stoi class, stol id, a negative id -> 0) and the
deserialized object as the value. `tools/planes_list.py` checks key == object id on every plane (no mismatch in the
17 parts).

### Cheap fallback (no full parse)
Every map key is a CString whose text matches `\{[0-9A-F-]{36}\}~-?\d+~-?\d+` and is immediately followed by a
WriteObject tag (`FF FF ...` or `0x80xx`). Use this only as a cross-check: the full grammar is what tells a real key
from bytes that happen to look like one.

### Worked bytes (NAKTO-BRAKE-BRACKET, archive offsets)
`+0x000` `FF FF 04 00 0F 00 "MastercamPlanes"` (#1) · `+0x015` `FF FF 03 00 0C 00 "SystemPlanes"` (#2) +
`00 01 01 00 00 00` · `+0x02d` Matrix33 v2 (#3) · `+0x03b` P3D v2 (#4) ... · `+0x322` count `19 00` (25) ·
`+0x324` key `2A "{00000000-...}~2~7"` · `+0x34f` `FF FF 04 00 05 00 "Plane"` (class #5, object #6) · `05 80`
(Plane level) · `FF FF 04 00 09 00 "PlaneBase"` (#7) · `FF FF 01 00 07 00 "PlaneID"` (#8) · GUID 16x`00` ·
`02 00 00 00` class 2 · `07 00 00 00` id 7 · `03 80` Matrix33 · `04 80` P3D ... · `03 "Iso"`.

## 4. What exists after loading (and what GetNextID returns)
- mccore `DbProcess::ProcessAssocPlanes` (FUN_1802d0590, called from ProcessAssocEntity FUN_1802cf2a0) takes the
  record's deserialized MastercamPlanes, runs `CheckPlane` on copies of each plane (results go into a list, the
  plane is not changed), then `Planes = filePlanes` (MastercamPlanes::operator= 0x1802acce0) and
  `DbViewMap::AddToPlanes`. It never calls `GetDbPlaneIdMap::Add`.
- `operator=`: when `this[0x18] == 0` -> `MapCopy` (0x1802b9080) puts each plane in again with `MapAdd`, keyed by the
  plane's own PlaneID (class 1 PlaneBase / class 2 Plane), so **ids are kept as stored**. When `this[0x18] != 0` ->
  `MastercamPlanes::Copy` (merge: `GetPlanePtrByID`, `Add` for planes not present, `Set` for the others); whether that
  path can renumber is NOT DECODED (it depends on `Add`'s id handling and the flag at +0x18).
- `DbViewMap::AddToPlanes` and `MapAdd`'s view branch both depend on `DbViewMap::GetAddViewsToPlanes`, which returns
  `false` (0x1803edda0): no planes are added from view entities.
- `GetDbPlaneIdMap` (old id -> new id) is filled only by `DbProcess::ProcessAssocViews` (FUN_1802d11e0: old `view_ent`
  records; "X8 and above MCX files should not contain view entities") and by mccore FUN_1802b19a0 (vtable-only
  caller, decompile times out, NOT DECODED). The two Process* functions assert that a file has only one of the two.
  So for X9 / 2017 parts the GetDbPlaneIdMap is empty and an op's stored plane id is used as is.
- `GetNextID(class) = GetHighID(class) + 1` (if `>= 0x8000`, the first free id is searched upward).
  `GetHighID(2)`: the std::map is ordered by `PlaneID::operator<` = (class, id, GUID); it looks only at the **last**
  element: if its class is 2 and its id > 0x33, returns that id, else **0x33**. So a new user plane gets id
  max(52, highest class-2 id + 1), as long as no plane of class > 2 exists (if one did, GetHighID(2) would return 0x33
  even with class-2 ids above 51; that follows from the code, there's no sample).
  `GetHighID(1)` goes through `SearchFirstNamedPlanePtr`; not needed here (user planes are class 2).
