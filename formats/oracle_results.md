# Oracle results: how close each port is to Mastercam

Every port is checked against Mastercam's own output: the toolpaths (NCI) and drafting records Mastercam stored in the corpus
parts. This file lists each oracle, how to run it, the latest numbers and the known gaps, so accuracy can be improved later.

**Recording**: `tools/tests/oracle_record.sh [regression summary.txt]` runs the port oracles, reads the regression's oracle
lines, and appends one row per metric to `tools/tests/oracle_history.tsv` (date, commit, oracle, metrics). A `+` after the
commit means uncommitted changes. Run it after every port change and commit the new rows with the change. `FULL=1` adds the
slow corpus-wide drafting value check; `SKIP_PORTS=1` records only the regression lines. To compare runs:
`grep -P '\tengrave\t' tools/tests/oracle_history.tsv`.

Distances are in part units (inch, or mm for METRIC parts). "ref->ours" is how far Mastercam's points lie from our path;
"ours->ref" is the reverse. Both are needed: one shows missing cuts, the other shows extra cuts.

Latest numbers: 2026-11-08 second 3D accuracy pass (waterline, optirough, raster, area roughing rows); 2026-10-26, master f4ac73b (Transform 983128a, Pencil after it); the 3D rows of the regression table 2026-11-08 (6e7b0d3). The 3D "cut length" values are the true feed length since 2026-11-08 (before: the sample count, which over-counted short moves).
